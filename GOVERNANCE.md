# Governance note: Car Care Agent

**Accountable person:** [YOUR FULL NAME], the sole builder and operator of this agent. Contact: [YOUR SCHOOL EMAIL].

**What data it reads and stores, and where.** The agent reads only what a visitor types into the chat and the car record in the side panel: make, model, year, mileage and service dates. That record and the last 16 chat messages are kept in the server's memory (RAM) under a random session ID. They are deleted after 3 hours without activity, or whenever the server restarts. Nothing is written to disk or to a database, and there are no accounts. The browser stores only the session ID. Each message and the car record are sent to Google's Gemini API to generate the answer. On Gemini's free tier, Google may use that text to improve its models, so the page asks visitors not to enter personal details. Only the make, model and year are sent to NHTSA (recalls and complaints) and to the EPA's fueleconomy.gov (MPG). The Gemini key is stored as an environment variable on Render. It is never sent to the browser, and any reply containing it is blocked.

**Where the human gate sits.** The only action that changes stored data is saving a service record or a new mileage to the car record. The gate sits between two steps. In the first, a specialist agent calls `propose_profile_update`, which only creates a pending request. In the second, the server applies that change to the record. In between, the chat shows an amber "Approval needed" card with the tool name and every argument exactly as the agent sent it (action, service, mileage, date), plus **Approve and save** and **Reject** buttons. The server writes the change only when that card's button is pressed, and each request can be decided once. No agent has a tool that writes directly.

**What a stranger with the link can do.** They can chat; edit and save their own session's car; trigger read-only lookups to NHTSA and EPA; and approve or reject changes to their own car record. They can also try prompt injection, and they can use up part of the shared free Gemini quota.

**What they cannot do.** They cannot see or change anyone else's session. They cannot make the agent save anything without clicking Approve, or send email, make payments, delete files, or reach any real system: none of those tools exist. They cannot get the API key: it never reaches the browser, and an automatic check blocks any reply that contains it. The agent is also instructed not to reveal its system prompt; eval case A2 tests this. They also cannot exceed the caps: 5 messages per minute per visitor, 2 conversations processed at once, 25 messages per chat, 5 reasoning steps and 8 tool calls per message, and 2,048 output tokens per model reply. The agent gives guidance, not a mechanic's diagnosis, and says so.
